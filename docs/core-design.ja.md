# コア設計と研究上の境界

**言語：** [中文](core-design.md) · [English](core-design.en.md) · [日本語](core-design.ja.md) · [Français](core-design.fr.md) · [Español](core-design.es.md)

## 設計上の問題

マルチエージェントまたはマルチロールのレビューには、次のような失敗パターンがあります。

1. **偽の独立性**：一つのモデルが五つの口調を使うだけで、推論経路は同じです。
2. **偽の合意**：同じ推測を五回繰り返したものを、五つの証拠として扱います。
3. **偽の精密さ**：根拠のない転換率、サンプル数、成功確率で専門的に見せます。
4. **ロールの逸脱**：機会発見者が実行を始め、実行者がユーザーの価値判断を代行します。
5. **議長の越権**：統合者が前段にない事実を持ち込む、または強い異論を黙って捨てます。
6. **実行に着地しない**：レビューは優れていても、今日できる検証行動や停止条件がありません。

## ガードレール

| 失敗パターン | 仕組み |
|---|---|
| 偽の独立性 | 共通のレビュー概要、一次見解の隔離、複数モデルの独立性を主張しない |
| 偽の合意 | 匿名相互レビュー、同一起源チェック、悪魔の代弁者 |
| 偽の精密さ | 証拠ラベル、`[実験閾値]`、情報源がなければ未知とする |
| ロールの逸脱 | 助言者ごとに一つの推論方法と明示的な責任境界を割り当てる |
| 議長の越権 | 議長は既に示された前提だけを統合できる。追加の検証行動は特定済みの未知に遡れる必要がある |
| 実行に着地しない | 無情な実行者の依存関係図と、議長の検証基準、チェックポイント、停止条件 |

## 助言者に自己申告の確信度を使わせない理由

高・中・低という自己申告は、結論の信頼性より文体の強さを測りがちです。代わりに次を記録します。

- 重要な根拠は何か。
- 最大の未知は何か。
- どの新しい証拠が結論を反転させるか。

議長の確信度は、証拠の質、推論経路の独立性、重要な未知、判断の可逆性だけを基礎にします。

## 少数意見を条件付きで扱う理由

少数意見は重要ですが、実際の少数意見がない場合に必須にすると、反対意見の捏造を誘発します。適切な扱いは次の通りです。

- 根拠のある少数意見がある場合は明示的に残す。
- ない場合は、最強の反論が検証に耐えたかを記録する。
- バランスのためだけに書いた反対を、本当の不一致として扱わない。

## 限界

- これは認知とプロセスの道具であり、法務、医療、金融、セキュリティなどの専門家の助言を置き換えません。
- 現実世界の証拠を自動取得することはできません。調査、インタビュー、実験、データ確認は実際に行う必要があります。
- 手続き上の隔離はアンカリングを減らせますが、一つのモデルや一組の情報源が持つ体系的な偏りをなくせません。
- 出力の質はレビュー概要の質に制約されます。対象、制約、目的が不明なら、仮定を補うのではなく確信度を下げます。

## 研究の方向性

1. 隔離された一次見解と順次議論を、仮定の多様性で比較する。
2. 同一起源チェックが、同じ理由を複数の証拠として数えることを減らすか測定する。
3. `[実験閾値]` 表示が、業界基準の捏造を減らすか評価する。
4. 実際の意思決定で議長判断の較正、可逆性、検証コストをバックテストする。
5. 単一モデルの隔離、実際のマルチエージェント、人間と AI の混合レビューの費用対効果を比較する。
