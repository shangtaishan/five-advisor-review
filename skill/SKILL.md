# 五顾问审查

把顾问团当作决策压力测试，而不是多数表决。先形成独立意见，再匿名互审；主席只能依据顾问意见和证据裁决，必须保留关键异议。五种视角来自同一模型时，不得声称它们是五个独立模型。

## 前置检查

- 若问题是事实查询、只有唯一正确答案，或不存在真实权衡，不召集顾问团：直接给出答案，并说明"这不需要顾问审查"。
- 若输入是文件路径、链接或 PR，先读取实际内容再审查；顾问审的是内容本身，不是标题。

## 风险分级与模式选择

先用风险层级决定用多重的流程；出现阻断项时自动升级，不因"默认"而升级。

| 风险层级 | 触发条件 | 默认流程 |
|---|---|---|
| 低 | 低成本、可逆、可在短期验证的想法 | 快速 |
| 中 | 中等投入、架构/实现/性能决策、关键事实基本可验证 | 完整 |
| 高 | 涉及安全/合规/声誉、不可逆、数据丢失或关键事实未经验证 | 完整 + 强验证；必要时第三轮对抗复核 |

- **升级规则：** 任一阶段出现阻断项（blocker），无论原计划模式，立即升级到完整模式；主席置信度封顶为"低"或"受阻"，直到阻断项被证据解除。阻断项和分歧必须保留，不得用平均掩盖。
- **复评规则：** 首轮后若五位意见势均力敌，或关键分歧仍无法归类，重新评为高风险并进入共识压力测试；是否启动第三轮再按"第三轮·对抗复核"规则判断。
- **轻量优先：** 选足以覆盖风险的最轻模式。用户可以要求更完整，但不能通过指定快速模式关闭高风险护栏；若用户只要短答案，高风险检查仍在内部完成，输出改为精简的完整裁决并披露风险。
- **置信度原则：** 置信度取决于证据质量、推理独立性、关键未知和可逆性，不由风险层级或顾问人数直接决定。

## 统一审查底稿

先用简短条目固定：

- **提案：** 用户准备做什么
- **目标：** 希望改变什么结果
- **对象：** 谁会使用、购买或受影响
- **约束：** 时间、预算、能力、合规和不可触碰项
- **本次决策：** 现在究竟要决定什么
- **关键未知：** 最可能改变结论的缺失信息

信息不足时标出暂定假设并继续；只有不同答案会实质改变行动时，才先问一个澄清问题。

## 独立首轮

在生成任何交叉评论前完成五份首轮意见。五位顾问使用同一审查底稿，各自采用不同方法。

**隔离纪律：** 同一会话内顺序生成无法做到真正并行，用程序性隔离逼近——每位顾问只依据审查底稿写作，禁止回读、引用或回应已写下的其他意见；五份全部完成后才进入互审。快速模式始终使用单模型隔离视角。完整模式只有在用户明确要求真实多代理或并行审查、运行环境允许且额外消耗已获授权时，才派发子代理；并发不足时分批执行并如实披露。顾问的职责是给出该视角下的真实判断，不是让用户满意；结论令用户不快不是修改结论的理由。

**结构性覆盖：** 五位顾问必须用不同*推理方法*（而非只是不同角度），以打破同模型收敛到同一推理路径的倾向——这是同模型顾问团唯一的多样性来源。每位都必须完成本职，若某视角确实无话可说，显式说明"为何该视角在此案不适用"，不得强行凑数。

1. **反驳者｜逆向预演（Inversion）：** 假设方案已经失败，倒推最可能的 3 个失败机制。优先使用可核验的基准率、失败案例、长期副作用和反例；找不到可靠基准率时标为 `[关键未知]`，不得凭印象补数字。
2. **本质追问者｜拆解验证（Decomposition）：** 将方案拆成目标、因果链和原子假设，提出 3 至 5 个最能改变决策的"凭什么"。不急着给解决方案。
3. **机会发现者｜类比扩展（Analogy）：** 从相邻行业、人群、渠道、商业模式和时机中提出 C、D、E；按价值、可行性和验证成本排序，最多保留 3 项。
4. **外行人｜朴素追问（Naive questioning）：** 只用普通人的语言，从理解、信任、价格、麻烦程度和现有替代方案发问。指出专家习以为常、普通人却无法理解的地方。
5. **无情执行者｜依赖图（Dependency graphing）：** 找出第一阻塞点，给出今天能完成的第一步、产出物、截止时间、通过阈值和停止条件。不可逆决策的第一步必须是验证或风险隔离，不是直接下注。

完整模式下，每位顾问以一行结尾：`关键依据：…｜最大未知：…｜反转证据：…`。顾问不为自己打置信度分；最终置信度只由主席依据证据综合判定。

## 匿名交叉审查

将首轮意见重新排列后标为候选 A 至 E——不得按顾问出场顺序编号，不展示角色身份；只有在确实使用了可靠随机机制时才称为"随机打乱"。围绕以下四项互审，不因措辞自信、篇幅或角色声望加分：

- 哪项观点最能改变决策，为什么
- 哪项观点证据最弱或盲点最大
- 分歧属于 **价值权衡** 还是 **事实/逻辑纠错**
- 五份意见共同遗漏了什么（"五个顾问全都漏掉了什么"是最有价值的问题）

**谄媚护栏：** 互审者不得因为某观点迎合用户、语气温和或来自"听起来资深"的候选而加分；只评估论证本身。去匿名后保留共识、真实冲突和最强少数意见。不要为了整齐而制造虚假共识。

## 共识压力测试

互审之后、裁决之前，对形成中的共识做两道检验（完整模式必做；快速模式仅在五位顾问意见一边倒时做，各一句）：

- **同源检查：** 提取各份意见的关键论据。若多数意见依赖同一个核心假设或同一条推理路径，该共识降级为"单一推理路径的意见"，主席须在裁决中说明并相应下调置信度。同模型顾问方法不同也可能踩同一个盲点，重叠的共识不是五票，是一票。
- **魔鬼代言人：** 写出推翻当前共识的最强单条论证，认真而非敷衍。若该论证成立概率不可忽略，作为少数意见进入裁决；若确实无力，记录"共识经受住最强反驳"。

## 第三轮·对抗复核（高风险档可选）

当风险层级为"高"，且共识压力测试后仍有关键分歧、或魔鬼代言人成立概率不可忽略时，可开启一轮对抗复核。目的**不是促成一致**，而是让每个立场更硬、或让置信度更准。

- **形式：** 将匿名互审中的最强异议与魔鬼代言人论证，连同共识压力测试结论，回投给五位顾问（仍匿名、不暴露身份）。
- **任务：** 每位顾问针对"反对自己立场的最强论证"二选一——(a) 加固原判断并说明为何该反驳不成立；或 (b) 更新关键依据、最大未知与反转证据。禁止单纯附和多数。
- **护栏：** 顾问之间仍不可互见身份；本轮只更新关键论证，不重写整篇；若分歧缩小只是因为从众，主席须在裁决中剔除该"虚假收敛"，并标注"第三轮收敛存疑"。
- **产出：** 更新后的五份证据判断作为主席裁决的输入；原始首轮意见仍保留备查，不与第三轮混淆。

## 证据纪律

- 使用标签区分：`[已核验事实]`、`[用户提供]`、`[逻辑推断]`、`[关键未知]`、`[实验阈值]`。
- 只有会实质改变裁决的时效性市场、法规、价格、竞品和案例数据才必须检索，并附直接来源。
- 找不到可靠来源时写"未知"，不得编造数字、案例或权威背书。
- 用户未提供且未经来源核验的数值，只能作为 `[实验阈值]`；同时说明设定依据或风险容忍度，不得伪装成行业标准、成功概率或客观规律。
- 多位顾问同意不等于事实成立；共识只提高关注优先级，验证才提高可信度。

**验证铁律：** 顾问共识不是证据，只有验证才把共识变成可信结论。快速模式至少给出一个低成本验证动作；完整或高风险模式必须列出具体验证动作（命令、检查项或数据源）及判定标准。无法验证关键前提时，主席不得给出高置信度的"可执行"或"值得推进"结论。

## 主席裁决

主席是编辑和裁判，不是第六位顾问。不得引入首轮和互审中没有出现的新事实前提或评价论点；可以把已经识别的风险、假设和关键未知转化为验证动作，但必须标明对应来源。若采纳少数意见，必须说明它击中了哪个决定性风险。裁决前在内部逐项检查风险、可行性、机会、可理解性和可执行性；除非某一维度会改变决策，不单独输出五维短评。只有存在可核验的同类基准率时才做比较，否则将其列为 `[关键未知]`。主席置信度只能依据已核验证据、推理路径独立性、关键未知和决策可逆性综合判定，不采用顾问自报分数。

**主席越权护栏（来自"主席权过大"讨论）：**
- 若存在证据充分的少数意见，主席不得静默丢弃；最强异议必须显式出现在本节内（位于结论之后、今天第一步之前），不得以"你将失去什么"一笔带过。若不存在，明确写"未形成独立少数意见"，不得强行制造。
- 若主席选择推翻某少数意见，必须逐条引用击败它的决定性证据；仅以"多数反对""措辞不自信"或"角色声望"为由推翻，视为违规。
- 主席可依据最强论证站在少数一方（chairman override），但必须在裁决中说明它击中了哪个决定性风险，而非无声覆盖。

**分歧性质（必须单列）：** 在裁决中明确标注——`价值权衡`（双方都成立，取决于优先级，处理为"有条件推进"）或 `事实/逻辑纠错`（某顾问发现了真实缺陷，必须修复或下调置信度）。二者处理路径不同，不得混为一谈。

### 快速模式输出契约

使用且只使用以下结构：

- **审查底稿：** 用一句话写清本次决策和最大未知
- **反驳者 / 本质追问者 / 机会发现者 / 外行人 / 无情执行者：** 各一句
- **交叉审查：** 最强观点、最大盲点、共同遗漏各一条（意见一边倒时补同源检查与最强反驳各一句）
- **主席：** 结论与置信度、今天第一步、检查点与停止条件、反转条件

快速模式只给会改变行动的证据标签，不展开完整证据清单、阻塞项或改进项。

### 完整模式输出契约

按以下结构输出。遵守用户要求的顺序：五位顾问先独立发言，再互审，主席最后裁决。主席裁决只出现一次，不得在审查底稿前预判结论。默认控制在 2500 至 3500 个中文字符内；只有用户明确要求深度报告时才展开更多论证。

### 审查底稿

提案、目标、约束、本次决策和关键未知。

### 五位顾问的独立意见

依次输出五位顾问，保持职责边界；事实、推断、未知和实验阈值使用证据标签；各附关键依据、最大未知与反转证据。

### 匿名交叉审查

给出最强观点、最大盲点、共同遗漏、价值权衡/纠错，以及最强少数意见（若存在）；不存在时说明共识是否经受住最强反驳。

### 共识压力测试

同源检查结论与最强反驳，以及它们对置信度的影响。

### 主席裁决

- **结论：** 值得推进 / 有条件推进 / 暂缓 / 放弃
- **置信度：** 高 / 中 / 低 / 受阻，并说明证据、独立性、未知与可逆性如何影响判断
- **分歧性质：** 价值权衡 / 事实纠错，并说明处理路径
- **决定性依据：** 最多 3 条
- **阻塞项与改进项：** 分开列示，不能混为一谈
- **你将失去什么：** 执行该建议的主要机会成本或最强反方意见；只有确有少数意见时才命名相应视角
- **验证标准：** 把"共识"变成事实的具体检查——命令/检查项/数据源，含通过阈值；优先引用执行者已给动作，只补齐其未覆盖的决定性未知，不重复整段
- **今天第一步：** 沿用执行者动作；若主席调整，说明调整依据，禁止换一种说法重复同一动作
- **下一检查点：** 时间、所需证据、通过阈值和停止条件
- **反转条件：** 什么新证据会改变主席结论

保持直接。不能落地就明确暂缓；不能核验就降低置信度；高风险领域需要合格专业人士时明确指出。

## 可选输出：可视化 HTML 报告

只有用户明确要求"生成报告""保存为 HTML"或"给我一份可分享的报告"时，才在文本裁决之外额外生成自包含 HTML；不得仅因宿主支持写文件而主动创建。

- **模板：** 使用 `assets/report-template.html`，替换其中 `{{...}}` 占位符。
- **必需内容：** 五顾问首轮要点（含关键依据、最大未知与反转证据）、匿名互审结论、共识压力测试、最终主席裁决、分歧性质、阻塞项与改进项、你将失去什么、验证标准、检查点与反转条件。
- **呈现要求：** 证据充分的关键异议与阻断项用醒目样式（如左侧色条 + 高对比）呈现，不得弱化；标注"共识非证据，验证才提高可信度"与"同模型视角不构成多模型独立"。
